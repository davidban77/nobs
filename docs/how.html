How it is built

One architect plans nobs and writes a contract for each slice: a short page that says what to build, which files to touch and which tests to add.

A factory session, an AI coding session, takes the contract and builds the slice on its own branch.

It writes the code and the tests, runs the six checks, and runs the commands for real against labs that it creates and removes again.

Then two reviews read the work: a technical review of the code and the tests, and a documentation review of every word a user sees.

When a review asks for changes, the factory session fixes them and the review reads the work again.

The architect reads the two reviews and opens the pull request.

David reads the pull request and merges it; nobody else merges.

Every slice leaves a record: what was built, every check with its output, the real runs and every change from the plan.

One rule stands above all others: when a step fails, nobs stops and passes on the error, and it never says "done" after a failure.

The older Python tools sometimes printed success after a failed step; nobs was built so that this cannot happen.
