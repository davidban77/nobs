nobs: one terminal tool for network labs

nobs is a command-line tool, written in Rust, for network labs and network observability workshops. A network lab is a small virtual network of routers and monitoring tools that runs on your own computer, in containers. nobs starts, checks, fixes and removes these labs with short commands. It replaces four older Python tools with one program. It also has a text user interface (TUI): a screen inside the terminal that you drive with keys.

Who it is for

nobs is for network engineers who learn or teach network observability: people who follow the book "Modern Network Observability" by David Flores, people in its workshops, and anyone who builds network labs with Docker and containerlab. Docker runs programs in containers. containerlab is a program that builds a virtual network from a topology file, with each network device as a container.

Status today

nobs is early, but most of its commands work today. It takes the place of these Python tools:

  • labcli: its 13 docker commands and 3 containerlab commands.
  • netobs, the tool of the book lab: its docker commands and its 7 lab commands. Its Nautobot helpers and its interface flap helper are not in nobs yet.
  • The workshops' nobs, the Python tool of the workshops: its 25 workshop commands and the setup, preflight and workshops commands.
  • labby: nobs follows its design. labby's project file and build flow come in a later step (see the roadmap).

Today 62 commands are in Rust: 13 docker, 3 containerlab, 7 lab, 10 sonda, 25 workshop commands, and 4 at the top (setup, preflight, workshops, tui). The full list is on the commands page.

Where it runs: nobs runs on a Mac (Apple silicon). containerlab runs only on Linux, so the containerlab and lab commands use a Linux arm64 build of nobs. That build runs inside clab, a Linux machine made by OrbStack, the Mac program that runs Docker and Linux machines.

Is the workshop ready?

status asks the seven services of a workshop if they are up. Here Loki, the log store, is not ready yet.

nobs nobs-t-one status
$ nobs nobs-t-one status

Grafana       http://localhost:3000  ok

Alertmanager  http://localhost:9093  ok

Some services are not ready yet: give them a minute, or check nobs nobs-t-one logs.

Bring the book lab up

lab deploy runs inside clab and brings up one chapter of the book lab, step by step, and waits until it is ready. The ... lines stand for the output of Docker, containerlab and Docker Compose.

orb -m clab <path> --dir <lab> lab deploy -s ch1 --sudo --network-name nobs-t-net --subnet 203.0.113.0/24
$ orb -m clab <path> --dir <lab> lab deploy -s ch1 --sudo --network-name nobs-t-net --subnet 203.0.113.0/24
lab deploy: creating network nobs-t-net (203.0.113.0/24)
...
lab deploy: deploying topology <lab>/containerlab/lab.yml
...
lab deploy: starting ch1 (project netobs)
...
lab deploy: waiting for 1 services and 2 nodes (up to 300s)
lab deploy: ready after <seconds>s
lab deployed: scenario ch1

Fill the source of truth

load-infrahub loads the devices, interfaces and BGP sessions of a workshop into Infrahub, the database that holds what the network should look like.

nobs nobs-t-one load-infrahub
