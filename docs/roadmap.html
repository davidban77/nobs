Roadmap

The work is cut into slices. A slice is one step of the plan, and it lands as one pull request. Slices 1 to 18 and slice 22 (the first terminal screen) are merged. These come next, in this order.

Slice 19: Nautobot helpers

Nautobot is the source of truth of the book lab: the database that holds what the network should look like. Two new commands, nobs utils load-nautobot and nobs utils delete-nautobot, fill it from the lab files and empty it again. A second load changes nothing, and every device gets the right device type. This step also names the arm64 cEOS file in the error line and the README.

Slice 20: The project file

A file nobs_project.yml describes a lab in the shape labby uses: the main settings, the nodes, the links and the variables. Templates turn it into a containerlab topology and the start configs of the devices, and nobs then builds the lab.

Slice 21: A replaceable source of truth

The code that talks to Infrahub moves behind one shared interface, so another source of truth can take its place without a change to any command or screen. The first command that uses it is nobs <workshop> devices.

Slice 23: Screens for Docker Compose and containerlab

New views in the terminal screen for the stacks and the containerlab labs.

Slice 24: Screens for the book lab, the workshops and the source of truth

More views: the book lab, a workshop, and the devices with their maintenance state.

Slice 25: Config push over SSH

nobs sends configuration to the network devices over SSH. Arista EOS and Cisco IOS wait for the Linux host.

Slice 26: Interface flap helper

A command that makes an interface of a device go down and up again over SSH, to test the alerts.

Slice 27: Release builds

Ready-made programs for macOS arm64, Linux x86_64 and Linux arm64. The x86_64 run waits for the Linux host.

Slice 28: A last full check

A test of every command, every flag and every exit code against the full list, and a check that the guides match the code.

The terminal interface

The first screen, nobs tui, works today: it shows the Sonda scenarios and lets you load and delete them with keys. It is a starting point. Before the next screen is built, a look-and-feel direction with three options is being written. It will appear here, with screenshots, once David has chosen.

The Linux host

Some work needs a Linux computer that runs no other lab. The real book lab with Arista cEOS routers waits for that Linux host, because cEOS does not run well on the Mac. The Linux half of the first milestone, SSH to Arista EOS and Cisco IOS, and the Linux x86_64 build wait for it too.
