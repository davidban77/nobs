Roadmap

The work is cut into steps. Each step lands as one pull request. These steps are done:

Nautobot helpers

Nautobot is the source of truth of the book lab: the database that holds what the network should look like. Two commands, nobs utils load-nautobot and nobs utils delete-nautobot, fill it from the lab files and empty it again. A second load changes nothing, and every device gets the right device type.

The project file

A file nobs_project.yml describes a lab in the shape labby uses: the main settings, the nodes, the links and the variables. Templates turn it into a containerlab topology and the start configs of the devices, and nobs then builds the lab.

A replaceable source of truth

The code that talks to Infrahub sits behind one shared interface, so another source of truth can take its place without a change to any command or screen. The first command that uses it is nobs <workshop> devices.

The screen

The terminal screen has workbenches for the devices, the services, the lab and the observability tools, and runs actions with keys.

Config push over SSH

nobs sends configuration to the network devices over SSH. Arista EOS and Cisco IOS wait for the Linux host.

Interface flap helper

nobs device flap makes an interface of a device go down and up again over SSH, to test the alerts.

Release builds

Ready-made programs for macOS arm64, Linux x86_64 and Linux arm64. The x86_64 run waits for the Linux host.

This step comes next:

A last full check

A test of every command, every flag and every exit code against the full list, and a check that the guides match the code.

The terminal interface

The screen works today. Plain nobs and nobs tui open it on the lab nobs finds from the folder you are in. It has the devices, services, lab and observability workbenches. An action that changes something runs only after you answer y to its question. With no lab, nobs tui shows the scenarios of a running Sonda server.

The Linux host

Some work needs a Linux computer that runs no other lab. The real book lab with Arista cEOS routers waits for that Linux host, because cEOS does not run well on the Mac. The Linux half of the first milestone, SSH to Arista EOS and Cisco IOS, and the Linux x86_64 build wait for it too.
